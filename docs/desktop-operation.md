# デスクトップ Blender を直接操作する設計

手元の PC で起動している Blender を Claude Code から直接操作するための設計。
接続手順そのものは [blender-mcp.md](blender-mcp.md) にあり、本書はどこで何を
動かすかという構成の決定と、その理由を記す。

## 前提となる制約

blender-mcp は 2 つのプロセスに分かれている。

- **アドオン側** — Blender 内でソケットを待ち受ける。`localhost` 固定でバインドし、
  ポートのみ変更できる（既定 9876）
- **MCP サーバ側** — Claude Code が stdio で起動し、アドオンへ接続する。接続先は
  `BLENDER_HOST` / `BLENDER_PORT` で変更できる

つまり **アドオンはループバックにしか口を開かない**。Blender と同じ PC 上で
MCP サーバが動いていれば、追加の設定なく届く。

## 採用する設計：すべてを手元の PC で動かす

```
手元の PC
┌──────────────────────────────────────────────┐
│  Blender（GUI）                              │
│    └ アドオン: localhost:9876 を待ち受け     │
│         ↑ ループバックのみ                   │
│  blender-mcp（uvx が起動）                   │
│         ↑ stdio                              │
│  Claude Code（ターミナルで起動）             │
└──────────────────────────────────────────────┘
```

外部にポートを開かず、認証も不要で、ネットワーク遅延もない。
`get_viewport_screenshot` がそのまま使えるため、レンダリングを待たずに
結果を確認できる。

### クラウド実行環境（Claude Code on the web）を使わない理由

クラウド側のコンテナから手元の PC の `localhost` には到達できない。
経路が存在しないため、設定では解決できない。クラウドセッションでできるのは
Blender 用スクリプトを書くところまでで、実行は手元で行うことになる。

## 役割分担

| 実行場所 | 担当 |
| --- | --- |
| 手元の PC の Claude Code | Blender の直接操作、ビューポート確認、レンダリング |
| クラウドセッション | スクリプトの作成・改修、ドキュメント、リポジトリ操作 |

本リポジトリの `scripts/blender/` は後者で書き、前者で実行することを想定している。

## 手元の PC で実行するときの前提

クラウドのコンテナ（Linux / apt 版 Blender / ヘッドレス）とは環境が異なるため、
スクリプトは以下を前提に書いてある。

| 項目 | デスクトップ | コンテナ |
| --- | --- | --- |
| OpenImageDenoise | あり。`use_denoising = True` で 128 サンプル程度で足りる | なし。サンプル数で潰すか後処理が必要 |
| ビューポート撮影 | 使える | ソフトウェア OpenGL では真っ黒になる |
| Poly Haven からの取得 | 使える | 外部通信ポリシーで遮断される場合がある |
| GPU レンダリング | `cycles.device = "GPU"` に変更可 | CPU のみ |

`scripts/blender/` のスクリプトはデスクトップ側を既定としている。

## 遠隔から操作する案を採らない理由

`BLENDER_HOST` を使えば、トンネル（SSH ポートフォワード等）経由で手元の
Blender に接続させることは技術的には可能になる。ただし採用しない。

**このソケットには認証が一切ない。** そして `execute_blender_code` は Blender 内で
任意の Python を実行できる。ポートに到達できる者は誰でも、その PC 上で
任意のコードを実行できることになる。公開トンネル（ngrok 等の URL を配る方式）で
露出させた場合、事実上そのまま乗っ取られる。

どうしても遠隔から操作する必要が生じた場合でも、最低限、

- 公開 HTTP トンネルは使わない
- SSH の転送に限定し、両端をループバックにバインドする
  （`ssh -N -L 9876:localhost:9876 <host>`）
- 使用後は必ずトンネルを閉じる

を満たすこと。それでも、手元で Claude Code を動かす構成のほうが安全かつ単純で、
遠隔にする利点はほとんどない。

## 運用手順

1. Blender を起動し、サイドバー（`N`）の **MCP for Blender** タブで
   **Start MCP Server** を押す
2. 別のターミナルで作業ディレクトリへ移動し `claude` を起動する
3. `/mcp` で `blender` が **connected** であることを確認する
4. スクリプトを使う場合は Scripting タブに貼って実行するか、
   Claude Code から直接指示する

Blender 側のサーバを先に起動してから Claude Code を起動すること。

## 作業中の注意

- **シーンは `.blend` に保存する。** 実行環境が落ちるとメモリ上のシーンは失われる。
  スクリプトから再構築できる状態を保つこと
- `execute_blender_code` は任意の Python を実行する。**作業前に保存する**
- MCP サーバはセッション開始時に読み込まれる。設定を変えたら Claude Code を再起動する
